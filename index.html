OCP is a configuration manager for people who use coding agents across multiple machines. Keep your agents, skills, plugins, and settings in sync from one shared source—not a trail of folders and files to copy by hand.

Currently works with OpenCode; other harnesses coming soon!

Stop rebuilding your setup on every machine.

Your laptop, desktop, and remote dev box should share the configuration you choose—without maintaining separate copies of every instruction, skill, and config file. Declare the shared parts once, keep them in Git, and let OCP generate your profiles on each machine.

Keep work-specific profiles and machine-specific settings without duplicating the whole setup. Sync the source when it changes, then get back to work.

Getting started

The examples below use OpenCode, the first supported harness. Start with a local source, then connect it to Git to sync across machines.

  1. Install OCP

    The installer downloads the release for your platform, checks its SHA-256 checksum, and installs it to ~/.local/bin/ocp.

    Terminal
    curl -fsSL https://raw.githubusercontent.com/nandorocker/ocp/main/install.sh | sh

    Prefer to read it first? Inspect the installer or browse releases. Add ~/.local/bin to your PATH if needed.

  2. Set up your source

    Terminal
    ocp setup

    Follow the prompts to choose your configuration source and machine name. OCP preserves your existing global OpenCode configuration during setup.

  3. Declare, apply, and switch

    Add profiles to your source directory, then render and activate one. The example below shows the files to create.

    Terminal
    ocp apply
ocp use focused
opencode

Want to undo setup? ocp reset restores the configuration OCP preserved and leaves your source directory untouched.

One source. A few ways to work.

Profiles

Your source is a directory of ordinary files. Put shared settings in ocp.yaml, then add a folder for each profile. A profile can extend another and override its settings.

my-agent-config/├── ocp.yaml└── profiles/ ├── everyday/ │ └── profile.yaml └── focused/ └── profile.yaml
One source to maintain.
Profiles generated from it.
ocp.yaml
version: 1

# Shared by every profile
config:
  formatter: true
profiles/everyday/profile.yaml
config:
  model: openai/your-coding-model
profiles/focused/profile.yaml
extends: everyday
config:
  model: anthropic/your-review-model

Model names above are placeholders. Replace them with IDs from your OpenCode provider. With these files, focused inherits the shared formatter setting and changes the model.

More than model presets

Profiles can also select shared agents, instructions, skills, and plugins. Keep local skills under skills/, reference them explicitly, and reuse agent definitions while changing their model assignments.

Machines & sync

Keep your source in a Git repository. On another machine, set up from that repository and sync:

Terminal · replace the example repository
ocp setup --repo git@github.com:you/agent-config.git --source ~/.config/ocp
ocp sync

ocp sync synchronizes with the current branch’s configured upstream, resolves locked Git-backed skills, and renders your profiles. With automatic commits enabled, it can also commit and push local source changes.

Shared doesn’t mean identical

Use a profile’s machines overlays for local settings, or hosts to render a profile only on named machines. Add host instructions in hosts/<name>.md.

Sync configuration, not secrets

Keep API keys, OAuth credentials, and session history outside your source repository. Each machine still needs its own OpenCode authentication.

A small set of useful commands.

Keep this handy
ocp setup
Initialize OCP and choose your source.
ocp apply
Render local configuration without Git sync.
ocp use <profile>
Activate a profile for subsequent OpenCode runs.
ocp run <profile> [args...]
Run OpenCode with a profile, without changing the active one.
ocp sync
Sync the source repository and render profiles.
ocp list / ocp status
See your profiles and current setup.
ocp reset
Detach OCP and restore the preserved configuration.

Run ocp help <command> for options. See the full command overview for import, the local UI, and other commands. upgrade is currently deferred.

A few things you might be wondering.

Common questions
Do I have to keep every machine identical?

No. Share the configuration you want in common, then use machine-specific overlays for local settings. Profiles can inherit shared definitions without giving up their own agents, skills, or model choices.

Does it work with Claude Code or Codex?

Not yet. OpenCode is the first supported harness; support for other coding-agent harnesses is coming soon. Today, OCP does not generate native Claude Code or Codex configuration. The examples in this handbook use the currently supported OpenCode integration.

Will it overwrite my existing setup?

Setup preserves your existing global OpenCode configuration so ocp reset can restore it. OCP also detects edits to generated profiles and refuses to overwrite drift non-interactively without an explicit override. Keep your own backup and edit the canonical source, not the generated files.

Do I need Git or multiple machines?

No. You can keep a local source and use ocp apply and ocp use on a single machine. Git becomes useful when you want version history or to share that source between machines.

Is OCP ready for me?

It’s an early project, best suited to people comfortable with YAML and the terminal. Start small, keep a backup, and check the release notes before updating. Reports from real setups help shape what comes next.
